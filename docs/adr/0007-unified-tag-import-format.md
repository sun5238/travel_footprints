# 文本导入格式：统一 @ 标签 + 只切不认解析方向

M2 便签导入不采用「多前缀标记 + 自由文本结构化识别」，改为**统一 `@` 实体标记 + 只切不认解析方向**。解析器只做封闭、廉价、可靠的事（切行、剥时间、命中本地已知城市），输出「骨架草案」供校正页人工确认；类别（scene/shop/landmark）、事件类型归属、坐标归属全部由校正页裁决。原因：自由文本开放词表识别（地名/店名）精度不可靠且离线不可行，多前缀标记要求用户记忆多套书写约定；统一 `@` 后解析器只有一条判别规则（时间语法优先、否则地名快照），确定性最高。代价是用户书写负担略增（每个地名都写 `@`、忘写则按续行归并），换来「绝不静默错认」。

关键细则：
- **全量必 `@`**：城市、POI、交通端点一律写 `@`，无宽容路径、无裸名表匹配（城市虽可查表但不用于文本识别）。
- **行内结构信号**：无时刻的 `@地名` = 城市候选（多个并列各自独立点亮）；带时刻的 = 事件候选；无 `@地名` 的日粒度区间 = trip 区间。
- **时间语法收窄**：仅覆盖至少明确月日的表达（`YYYY-MM-DD` / `MM月DD号` / `MM.DD` / 区间 `到|至|~|～`），排除「周六晚上 / 初五」等相对/农历场景。
- **封闭剥离**：星级（`(\d|[一二三四五])星` / `★\d`）仅剥行内紧贴时刻后的第一个；交通方式（封闭词表约 10 词）剥为候选；剥出的值预填校正页、人工可改。
- **轨迹并入 visit**：轨迹 = 带轨迹增强字段的 visit（`gpx_path` / `drawn_geojson` / `difficulty`），不单设事件类型；里程/爬升/结束时刻为 GPX 派生值，不落列。
- **坐标三级兜底**：照片 EXIF GPS → 校正页地图点选 → 留空坐标态；不引入在线地图服务（高德/百度需要开发者账号注册 + 外发数据，不合铁律）。
- **时区口径**：便签时间按行程所在时区解释（`trip.tz`，默认 `DEFAULT_TIMEZONE`），照片按 EXIF offset 原样提取，两者并存（见 ADR-0006）。

否决了「轻格式多前缀（`- 店/交通/轨迹`）」与「在线 POI 搜索补坐标」两条路线。影响范围：解析模块、校正页交互、visit 属性和事件模型。完整设计见 [import-draft.md](../import-draft.md)。
