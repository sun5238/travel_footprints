# M2 文本导入设计草案（只切不认 + 三级坐标兜底）

> 状态：2026-09-20 与用户多轮评审收敛，作为 M2 导入模块的实现依据。
> 覆盖：解析范围、日志格式、坐标来源、分店/归属裁决、点亮粒度、事件标签与看板统计、校正页交互、事件属性口径（轨迹并入 visit）。
> 关联：[DESIGN.md](DESIGN.md) 第 5 节导入流程、[ADR-0004](adr/0004-rule-based-parsing-llm-off.md) 规则解析决策。

## 1. 解析范围：只切不认（不做结构化识别）

旅行便签导入**不做自由文本结构化识别**。解析器只做三件廉价、可靠、封闭的事，输出「骨架草案」供校正页人工确认：

| 步骤 | 做什么 | 结果 |
|---|---|---|
| 切行 | 一行一事件；连续不以 `#`/`@` 开头的行归并为上一事件评价正文 | 事件行列表 |
| 剥时间 | 识别 `YYYY-MM-DD` / `YYYY.MM.DD` / `MM月DD号` / `MM.DD` / `HH:MM` 及区间 ``到|至|~|～``；日期状态自上下文继承 | 每条候选的日期上下文 |
| 命中已知城市 | 仅当文本与本地 `City` 表完全匹配才认作城市，否则原文保留 | 城市归属候选 |

**明确排除**（不做）：

- 开放词表地名识别（jieba / 行政区划库 / 训练型 NER）
- 事件类型判定注册表：`->`、`登顶`、`结束` 等关系词**不用于类型判定**，仅在校正页作「疑似交通/疑似轨迹」的提示符，判定权在人工
- **不开放识别**：地名/店名等开放词表不识别（这是要 @ 的原因）；但 **封闭可剥取项开剥**：
  - 星级（`(\d\|[一二三四五])星` / `★\d`）→ 正则剥为 `rating` 候选
  - 交通方式（`高铁/飞机/自驾/徒步/船/其他`，约 10 词封闭词表）→ 剥为 `mode` 候选
  - 剥出的值只是候选，「命中模式」即可归属（visit 收星级、transport 收方式），校正页确认后才落字段；剥离失败/缺失则留在原文，不静默断言
- LLM 解析（含本地模型，ADR-0004）
- `correction` / `dictionary` 学习表和开放识别开关（本期只留接口位，不建实表）

原则不变（DESIGN 5.1 / ADR-0004）：**解析结果先展示后入库，绝不静默错认**；无法解析的原文整段保留、可全文搜索兜底。

## 2. 日志格式：统一 `@` 标签（v2）

用**单一 `@` 实体标记**替代原有 `- 店` / `- 交通` / `- 轨迹` / `- 备注` 多前缀。类别（scene/shop/landmark）判定全部推迟到校正页。

### 2.1 行分类

| 行类型 | 判定 | 产物 |
|---|---|---|
| 标题行 | 以 `# ` 开头 | `Trip.name`（可选，缺省由首个城市+区间推断） |
| 实体行 | 含 `@` 标记的 token | 时间 / 地名（见 2.2） |
| 续行 | 不以 `#`/`@` 开头 | 归并上一事件评价；无前置事件 → `Trip.note` |
| 空行 | 空白 | 忽略 |

### 2.2 `@` 词法规则（完全封闭）

```
见到 @ → 跳过（至多一个）空白 → 贪婪取 token
token 边界 = 空白 / 关系词(->、~、～) / 行尾 / 下一个 @
```

- 规范写法 `@token` 紧贴不加空格；宽容接受 `@ 成都`（跳一个空白再取）。
- **不对称关键规则**：`@` 与 token 可紧贴，但 **token 与后续字段（时刻/星级/评语）必须有空白或关系词分隔**。`@陈麻婆豆腐4星` 会把「4星」吃进地名而解析失败；正确为 `@陈麻婆豆腐 4星`。
- `@token` 判别优先级：先按时间语法命中（见 2.3），否则记为地名原名（作为名称快照）。
- **全量必 `@`**：城市、POI、交通端点一律写 `@`，无例外、无宽容路径、无裸名表匹配。城市虽可查表，但**不提供「裸名自动识别城市」**——标签唯一、机制一条规则到底，实现最简、确定性最高。
- **无宽容路径的落定**：忘写 `@` 的行首地名（如 `春熙路 14:20 …`）按续行规则**归并入上一条事件评价原文**，不尝试恢复为地名——这是「按语法归类」而非「静默错认」，不得在实现中开「识别无 @ 地名」的后门。
- **行内实体信号（时刻 = 事件性开关，地名 = 事件必要条件）**：
  - 名字对照时间语法：先验时间，否则记地名；
  - 无时刻的 `@地名` → **城市候选**（点亮）；同一行多个无时刻地名并列 → 各自独立为城市候选；
  - 带时刻的 `@地名` → **事件候选**（visit / 轨迹 / transport）；
  - 归类优先：地名是否在场决定「城市 vs 事件」，时刻粒度决定「trip 区间 vs 事件」。

### 2.3 时间语法（收窄至「至少明确月日」）

- 全日期：`YYYY-MM-DD` / `YYYY.MM.DD` / `YYYY/MM/DD`
- 月日：`MM月DD号` / `MM月DD日` / `MM.DD` / `MM-DD`（缺年 → 默认当年，跨年按 `DEFAULT_TIMEZONE` 处理）
- 区间：`START 到|至|~|～ END`；END 可省略年/月（沿用 START）→ `[start, end_exclusive)`（含结束日整天）
- 时刻：`HH:MM`，可选，跟在事件地点之后
- 日期状态继承：`@2号` 只给「日」，年/月自上下文（区间月份）补齐；刷新后后续行继承至再次覆盖
- **跨月/跨年消歧**（区间跨多个月时）：按「最近一次明确年月」继承；无明确年月则解析为「离区间起点最近的该日」；仍不确定的行标灰交校正页，不静默猜
- **trip 区间 vs 事件区间的区分（结构信号，无需词义）**：无 `@地名` 的日粒度区间行（如 `@2026-10-01 ~ 2026-10-07`，无 `HH:MM`）判定为 **trip 区间**（必在便签顶部/首事件前）；有地名 + `HH:MM` 的区间则判定为事件（轨迹/visit 时段）。灰色场景（区间中途出现/两个区间）交校正页。

### 2.4 端点归属 / 星级剥离 / 时区（三处收敛）

**transport 端点归属（裂缝 4，可压 M3）**：
- `TransportLeg` 端点仅作文本快照（`from_text`/`to_text`，现有字段），不做强制的城市归属校验——端点（重庆北/成都东）归属哪个城市是常识而非旅行记录；
- 校正页提供可选「归属城市」选择器（从本地 `City` 表选），缺省不填（悬空可显示）；不新增表结构。

**星级剥离的取样规则（裂缝 5）**：
- 仅剥**行内紧贴时刻 token 之后的第一个 `N星`/`★N`**，且一行只剥一个；
- 出现在正文深处、无时刻锚的「5星大厨」类文本**不剥**（无时刻锚 → 不命中）；
- 剥出的值预填校正页 `rating` 字段、带「解析自原文」标记，人工可改；少剥例外留给人工填。

**跨时区统一口径（裂缝 6）**：
- 便签时间按**行程所在时区**解释（`trip.tz`，默认 `DEFAULT_TIMEZONE`）；`visit.at_tz` 继承 trip.tz，校正页可逐条改；
- 照片时间按 **EXIF offset** 原样提取（ADR-0006 既有约定），与便签时间并存、不互相覆盖；
- 解析器解析时用 `DEFAULT_TIMEZONE`；行程日后设定 tz 可复核派生 epoch，**不自动改存储**。

### 2.5 示例（权威样例）

```text
# 国庆成都行
@2026-10-01 ~ 2026-10-07
高铁票要提前一周抢
@重庆 @成都
@重庆北 08:30 -> @成都东 11:00 高铁
@宽窄巷子 14:20 5星 人很多，盖章和糖画有意思
（青羊宫店附近，人特别多）
@陈麻婆豆腐 19:30 4星 麻婆豆腐很下饭，服务一般
@青城山 08:00 - 11:20 登顶 - 16:30 结束
```

- 「高铁票要提前一周抢」（首个事件前、无 `@`）→ `Trip.note`。
- 「（青羊宫店附近…）」→ 归并上一条评价正文。
- 交通行两端点都必须 `@`；缺失时按 `->` 上下文尽力恢复，仍不能恢复整行保留原文进校正页。
- 轨迹行（`@青城山 08:00 - 11:20 登顶 - 16:30 结束`）= 单地名 + 时间区间，**并入 visit**（同一次到访携带轨迹），不建独立轨迹事件；活动类型由校正页 `label` 定为「爬山／徒步」等。
- 示例中的 `5星`、`4星` 由正则剥为 `rating` 候选；`高铁` 由封闭词表剥为 `mode` 候选（§1 剥离开启），校正页确认后落字段。

## 3. 坐标来源：照片 GPS 自动为主，人工兜底

```
导入一个 visit
  ├─ 照片带 EXIF GPS?
  │    ├─ 有 → 自动取坐标
  │    │     ├─ 紧凑(跨度≤500m) → 中心点(pos_kind=point)
  │    │     └─ 离散(>阈值)     → 入口/首张锚点(pos_kind=entry)  [景区大范围]
  │    └─ 无 → 坐标空
  └─ 校正页人工兜底
       ├─ 地图点选补坐标（用户知道大致位置时）
       └─ 仍无 → 留空坐标态，visit 照存、点亮暂缺
```

- **不能依赖地图 SDK 获取 POI 类型/坐标**：项目默认全离线，在线地理编码/POI 搜索（DESIGN 第 9 节）明确「关」。离线 `.mbtiles` 瓦片只含渲染几何，不含结构化 POI。
- **不引入在线地图服务**（高德/百度 API）：需要每个用户注册开发者账号，门槛过高；且触发铁律 1 外发。网页爬取违反 ToS、仍外发，不做。仅保留「用户本人开网页查看再人工补录」作为合法补充（非程序行为）。
- 类型（scene/shop/landmark）不靠坐标推断，由校正页点选。

## 4. 分店/归属裁决：坐标=弱信号，校正页=最终裁决

**不做**基于坐标的自动去重合并。身份判定分三层：

| 层 | 依据 | 是否自动 |
|---|---|---|
| 无损合并 | 城市+名称一致 且 无坐标冲突 | 自动 |
| 疑似分店提示 | 城市+名称一致 但 GPS 相距>阈值 | 弱提示，不自动 |
| 身份裁决 | 校正页决策 | 人工 |

流程（同名「陈麻婆豆腐」第二次到访）：

1. 不自动合并；
2. 校正页展示：已有 N 次到访 + 各坐标 + 上次时间；GPS 相距远 → 标注「疑似不同分店」；
3. 用户选「挂已有 / 新建分店 / 忽略提示合并」；
4. 即使选错，`place_name_snapshot` 保留原文，可全文搜索兜底。

关联 DESIGN 第 4/11 节：同名分店并存、不强制合并；合并同名 POI 是手动触发能力。

> 归属裁决**只适用于 visit**（含带轨迹的 visit）；transport 是段文本快照，不发生「挂已有/新建分店」去重。

## 5. 点亮粒度

| 层级 | 做法 | 数据来源 |
|---|---|---|
| 城市级 | 地图点亮「去过」的城市 | 内置城市中心坐标表（约 300–500 城，几百 KB，作者/用户维护，离线打包） |
| POI 级 | 进入城市后点亮具体地点 | 坐标三级兜底（照片 GPS / 点选 / 留空） |
| 乡镇级 | **不做**（对旅行记忆无增量，坐标缺失、设计上无位置） | — |
| 国外 | 记名称快照不点亮；将来可选 GeoNames/自建国外城市表，路线与国内同构 | 后置可选增强 |

> **城市表职责收严**：内置城市中心坐标表**只用于点亮坐标**，不参与文本识别——识别全部走 `@token`（全量必 `@`）。这也使城市表成为一份纯离线静态数据，无解析、无匹配、无歧义。

**关键分线**：`visit` 去重判定 = 城市 + 名称文本；坐标只用于展示与分店弱提示，**不参与 identity 判定**，故景区大范围照片不会散成多家。

## 6. 事件标签与看板统计

用于「爬山 X 次 / 古镇 X 次 / 漂流 X 次」等统计。

### 6.1 内置标签目录（静态）

```
爬山 🏔  徒步 🥾  骑行 🚴  露营 ⛺  漂流 🚣
越野跑 🏃  滑雪 🎿  溯溪 💧  古镇 🏘  美食 🍜
古迹 🏛  海滩 🏖  雪山 ❄  演出 🎭  城市漫游 🚶
```
静态目录（前端打包，非数据库表），每项带内置图标（emoji/内置 SVG，不引外部图标库）。

**轨迹活动类型 = `label`**：爬山 vs 徒步 vs 骑行…统统是 `label` 内置目录的选项（运动类已扩入），不单独设字段；任何新场景走 label 自由输入兜底。

### 6.2 数据模型

- `Visit` 加 `label: str | None`（**单值主活动标签**，看板按此聚合 count，稳定干净）；
- **轨迹 visit 必须带 `label`**（活动类型=爬山/徒步/骑行…，校正页必填）——否则「爬山 X 次」等统计无依据；
- `Visit.tags` 保留多标签自由输入（不进看板统计）。

### 6.3 看板聚合

- `dashboard()` 增加返回 `label_stats: [{label, icon, count}]`（`SELECT label, COUNT(*) ... GROUP BY label`）；
- 前端统计卡动态渲染标签计数卡（有数据才显示）。

### 6.4 自定义扩展

- 编辑页/校正页：内置目录下拉 + 自由输入框；
- 自定义标签直接入库（`label` 为文本，无需外键/迁移），看板按文本聚合，无图标则用兜底图标；
- 新增内置标签 = 改静态目录，无需迁移。

## 7. 数据模型增量（本期实现）

| 位置 | 增量 | 说明 |
|---|---|---|
| `backend/travel/media.py` | EXIF GPS 读取（Pillow `_getexif`，纯本地） | 读不到不报错；填 `Media.gps_lat/lng` |
| `Visit` | 加 `label`（主标签）、`companions`（同行人，可空）、`pos_kind`（none/point/entry） | schema 版本化迁移 |

| `TransportLeg` | 加 `price`（票价，可空） | schema 版本化迁移 |
| ~~独立 `Trail` 表~~ | **并入 visit**：轨迹 = visit + 轨迹增强字段，不再单设事件类型 | 数据迁移（如已有 trail 数据 → visit） |
| `dashboard()` | 加 `label_stats` 聚合；**移除 `distance_km`（总里程）** | M2 无 GPX 数据源（GPX 属 M3），统计卡先不体现 |
| 静态 | 标签目录 + 图标（前端打包） | 无迁移 |
| 城市中心坐标表 | 内置 CSV（城市级点亮） | 离线打包 |

> **属性实现口径**：本次新属性（`Visit.companions` / `TransportLeg.price` / `Visit.difficulty`）直接建真实可空列，不做 JSON 袋——用户明确点名的固定需求，建列即可统计、可校验，旧数据 NULL 天然兼容。事件属性**不支持用户自定义扩充**（收益低 + 前端动态表单难 + 跨设备迁移兼容性差）；`label`（主活动标签）保留为自由文本自定义，统计按文本聚合。

> **里程/爬升/结束时刻不存列**：轨迹 visit 若有 GPX，这些值从 GPX 的 trkpt 实时/导入时派生，数据根内的文件就是事实源，不落 visit 列、不会失真。结束时刻同理（GPX 尾部即结束点；无 GPX 需手动填才作可选注释）。

> 说明：`Media.gps_lat/lng`、`City.lat/lng`、`Place.lat/lng` 字段与前端渲染/后端写入接口均已存在（见 `models.py` / `api.py`），坐标链路无需新接口。

## 8. 校正页交互（事件编辑 / 照片批量 / 属性分区 / 导入提示）

### 8.1 事件增删改

**后端现状**（`api.py`）：事件类型为 visit（含轨迹增强）/ transport 两种（轨迹并入 visit）；trip/place 有 PATCH，visit/leg 无 PATCH；全类型有单条 create/delete。

| 操作 | 现状 | 需补 |
|---|---|---|
| 新建事件 | ✅ 各类型 create 已有 | 前端加「+ 事件」入口（校正页/详情页），弹出类型选择（**visit / transport** 两种；轨迹并入 visit）→ 调对应 create |
| 删除事件 | ✅ 单条 delete 已有 | 前端每事件卡加删除按钮（确认一次） |
| **修改事件** | ❌ visit/leg 无 PATCH | 补 `PATCH /visits/{id}`、`PATCH /legs/{id}`（trail 并入 visit，无需单独 trail 接口） |

修改设计：
- 后端 PATCH 复用 `TripPatch`/`PlacePatch` 的「Pydantic 可选字段 → 仅更新非 None」模式（`schemas.py` 已有先例）；
- 前端「编辑」按钮复用现有 `visitForm`（`app.js` 已有）——同一表单切换 create/edit 模式，预填当前值；
- 属性必填校验在编辑时同样生效（见 8.3）。

### 8.2 照片批量取消选择

**互选集合交互**：

- 前端照片网格加勾选框 → `selectedMedia` 集合；
- 顶栏「已选 N 张」+ [批量取消选择] [批量删除]；
- 「取消选择」= 把照片从 visit 上**解绑**（`Media.status` → pending），**不删除文件**；
- 「删除」= 调现有单条 `DELETE /media/{id}`（或补批量接口，一次事务避免 N 次往返）。

**后端建议补一个批量接口**：`PATCH /media/batch`（`{ids, action: unassign|delete}`），单次事务处理 N 条，避免前端循环 N 次调用。

### 8.3 属性必填/选填分区

按事件类型各定义「属性表」，必填保底、选填从宽：

```text
Visit(含轨迹增强)  必填: at_local(时间)  place_name_snapshot(地点快照)
                   —— 轨迹 visit 另必填: label(活动类型 = 爬山/徒步/骑行…)
                   选填: rating  review  tags  companions
                         gpx_path  drawn_geojson  difficulty
Transport          必填: from_text  to_text  mode
                   选填: price  出发/到达时刻  备注

必填 = 保存前校验（缺则标红/拦截）
选填 = 空值照存(NULL)，“有填无空”
```

设计要点：
- **事件最小可用** = 必填 时间 + 地点快照，星级/评价等选填补全——用户不填星级照样能存，符合「先展示后入库、绝不静默丢弃」；
- 必填只是保证「这确实是一条事件」，不是要求全字段；
- 属性分区（必填/选填）是**表单 + 校验层**概念，不改表结构（列仍可空）；
- **自动剥离与校验层衔接**：星级/交通方式由解析器封闭模式剥离（§1），剥出的候选**直接预填校正页表单对应字段**（`rating` / `mode`），用户确认/修改后才入库；类型仍是人工判定，剥离不替代判定。

### 8.4 导入成功「已备份可删」提示

导入完成后全局提示条（toast/banner）：

```
照片/视频已备份至本机服务器（哈希去重确认入库）
➜ 可删除手机/相机上的原件，释放空间
[知道了] [查看备份]
```

- 隐私友好的引导，对应 DESIGN「手机厂商云备份是安全网」的延伸——到本机即等于备份；
- 动词用「**可**删除」而非「建议立即删」，删除是用户选择；且前提是「已哈希去重确认入服务器」；
- 纯前端提示，不需要新后端；
- 删除动作交给用户在自己手机的文件管理器完成（软件不代删原件，符合「数据自包含」）。
