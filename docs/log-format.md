# 预设日志格式（推荐便签写法）

> 目的：文本导入阶段的解析器按本格式优先结构化，把「同一件事能被多种写法描述」的歧义降到最低。
> 规则：预设格式不是硬性门槛。自由文本仍会走规则 + 词典尽力解析并进入校正页；解析不了的部分保留原文，绝不静默丢弃。

## 核心原则

1. **一个便签 = 一段行程**：每条便签是一个完整行程，导入时生成一个 trip。
2. **一行一个事件**：每条城市/地点/交通/轨迹占一行，方便程序切分。
3. **时间写全**：日期写到 `YYYY-MM-DD`，时间写到 `HH:MM`，避免歧义。
4. **城市先行**：地点默认归属最近一次出现的 `@城市` 行。

## 元素规范

| 元素 | 行首标记 | 示例 | 映射 |
| --- | --- | --- | --- |
| 行程标题 | `# ` | `# 国庆成都行` | trip.name |
| 行程时间 | `时间：` | `时间：2026-10-01 ~ 2026-10-07` | trip.start/end |
| 城市 | `@` | `@成都` | city（点亮） |
| 日期小节 | `## ` | `## 2026-10-02` | 后续事件归入该日期 |
| 交通 | `- 交通 ` | `- 交通 重庆北 08:30 -> 成都东 11:00 高铁` | transport_leg |
| 景点/地标 | `- ` | `- 宽窄巷子 14:20 人很多，糖画有意思` | place(scene/landmark) + visit |
| 店铺/美食 | `- 店 ` | `- 店 陈麻婆豆腐 19:30 5星 麻婆豆腐很下饭` | place(shop) + visit |
| 爬山轨迹 | `- 轨迹 ` | `- 轨迹 青城山 08:00 - 11:20 登顶 - 16:30 结束` | trail |
| 备注 | `- 备注 ` | `- 备注 高铁票提前一周抢` | trip.note 追加 |

## 写法细则

- 星际：行内写 `5星`、`4星` 或 `★5`（0-5，缺省不填）。
- 一个地点下的长评价可以换行续写：连续不以 `- / @ / ## / # / 时间：` 开头的行，归并到上一事件作为评价正文。
- 店铺与景点用 `- 店 ` 区分，店名不准确或有多家分店时，校正页让用户手选/手动标记坐标（见 DESIGN.md 第 5 节）。
- 多城市行程按时间顺序连续写 `@城市`，同一城市反复到达就再次写 `@城市`（路过不点亮，只有产生到访记录才点亮）。
- 照片/视频不写进文本：导入后按「时间 + 地点」挂靠到 visit，见 DESIGN.md 5.2。
- 实况照片按「同名 HEIC + MOV」或「单文件内嵌视频」处理，见 DESIGN.md 5.2。

## 完整示例

```text
# 国庆成都行
时间：2026-10-01 ~ 2026-10-07

@重庆
- 交通 重庆北 08:30 -> 成都东 11:00 高铁

@成都
- 宽窄巷子 14:20 5星 人很多，盖章和糖画有意思
- 店 陈麻婆豆腐 19:30 4星 麻婆豆腐很下饭，服务一般
  （青羊宫店，两人 128 元）

## 2026-10-03
- 太古里 10:00 逛街，看了裸眼 3D
- 店 冒椒火辣 12:30 4星 串串好吃但排队久

- 轨迹 青城山 08:00 - 11:20 登顶 - 16:30 结束
- 备注 青城山要提前预约，穿舒服的鞋
```

## 解析优先级

1. 预设格式行优先结构化（按上表标记切分）。
2. 无法命中标记的行走规则 + 词典（日期/交通词/城市名/常见动词）。
3. 仍无法解析的原文整段保留，进入校正页，可全文搜索兜底。
4. 每次人工校正写入 `correction` 标注库并回填 `dictionary`，后续识别率递增。
